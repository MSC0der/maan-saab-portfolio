# MAAN SAAB — IMMERSIVE WORLD ART DIRECTION

## Master Visual Source of Truth

The visitor does not simply scroll through a portfolio. They travel through an interactive 3D representation of Maan Saab's engineering systems, work, journey and problem-solving.

Experience flow:

SYSTEM ENTRY → ENGINEERING CORE → ARCHITECTURE → PROJECT SYSTEMS → ENGINEERING JOURNEY → DSA LAB → SYSTEM COLLAPSE → CONTACT

---

## 01 — SYSTEM ENTRY

Feeling: entering a system, not waiting for a website.

Start almost completely dark with faint geometry, distant particles and a barely visible Engineering Core.

Minimal UI:

SYSTEM INITIALIZING...
CORE ........ ONLINE
NETWORK ..... ONLINE
ENVIRONMENT . READY

[ ENTER SYSTEM ]

The loading/entry sequence must be brief. Camera starts outside the environment and approaches the Core.

---

## 02 — ENGINEERING CORE

The Core represents Maan Saab. It is not a logo, stock model, reactor, spaceship or decorative hub.

It is a procedural engineered object containing:

- outer structural cage
- segmented structural ring
- energy ring
- inner architecture
- radial components
- docking ports
- crystalline central hub
- base gyro structure
- micro satellites
- selective emissive elements

Technology nodes orbit around it:

NODE.JS, ANGULAR, TYPESCRIPT, MYSQL, MONGODB, AWS

Nodes exist at different depths and are actual spatial objects, not flat labels.

HTML UI:

MAAN SAAB
FULL STACK ENGINEER

Building scalable systems,
APIs & digital products.

[ EXPLORE SYSTEM ] [ VIEW RESUME ]

Use only confirmed existing portfolio metrics.

---

## 03 — ENGINEERING ARCHITECTURE

Do not fade into a Skills section.

The Core physically transforms into the architecture.

Scroll causes:

1. Core expands.
2. Outer rings separate.
3. Inner architecture opens.
4. Technology nodes move outward.
5. Connections stretch.
6. Structural nodes appear.
7. Camera moves deeper into the system.

Conceptual hierarchy:

BACKEND / FRONTEND
 ↓
NODE.JS / ANGULAR
 ↓
DATABASE
 ↓
MYSQL / MONGODB

This must exist as a genuine 3D spatial hierarchy.

Selecting a node highlights its relationships and displays real portfolio information in an HTML inspector.

## 06 — DSA LAB

DSA becomes an interactive engineering laboratory.

The environment becomes darker and more open.

Modules can include only concepts represented by actual portfolio/content data:

Arrays
Hashing
Linked Lists
Trees
Graphs
Binary Search
Sliding Window
Two Pointers

Do not make ordinary cards.

Example Array:

[04] [12] [07] [19] [03]

Example Two Pointer:

L → [04] [12] [07] [19] [03] ← R

Example Binary Search:

[03] [04] [07] [12] [19] [23] [31]
              ↑
             MID

UI:

BINARY SEARCH
Time Complexity O(log n)
Space Complexity O(1)

[ RUN ] [ RESET ]

The first goal is visual demonstration, not a full algorithm editor.

Everything returns to the Engineering Core.

Everything returns to:

CORE

This is the payoff of the experience.

Camera pulls back slightly and the world becomes quiet.

# WORLD-WIDE VISUAL LANGUAGE

Base: #05070B
Structural: #111923
Primary energy: #22D3EE
Secondary energy: #8B5CF6
Text: #EAF6FF
Muted: #64748B

Color behaves like illumination, not paint.

Most of the environment remains dark.

---

# MATERIAL LANGUAGE

Structural: dark graphite / metal.
Energy: selective emissive cyan.
Secondary: restrained violet.
Glass: used sparingly.
Data: small bright particles.

Avoid making everything transparent or heavily bloomed.

---

# CAMERA LANGUAGE

The camera is the storyteller.

Entry: far away.
Core: observing.
Architecture: moving inward.
Projects: moving between systems.
Experience: following a path.
DSA: exploring objects.
Collapse: returning toward Core.
Contact: settling.

Camera movement must be smooth and intentional.

---

# MOTION LANGUAGE

Every animation has meaning:

Core rotation = system is alive
Energy flow = active engineering
Data particles = information moving
Node movement = architecture changing
Ring separation = system opening
Project clustering = systems being built
Timeline path = career progression
Algorithm animation = problem solving
Collapse = everything originates from Core

Do not animate elements merely because animation is available.

---

# UI LANGUAGE

The UI is an information layer over the world.

Use:
- real HTML
- accessible text
- restrained translucent surfaces
- thin borders
- technical metadata
- strong typography
- minimal HUD

Do not turn the experience into a dashboard.

Avoid giant panels, excessive glassmorphism, fake system terminology, unnecessary cards and excessive neon.

**3D creates emotion. UI communicates information.**

---

# NAVIGATION

Keep navigation minimal:

MAAN SAAB

SYSTEM
ARCHITECTURE
PROJECTS
EXPERIENCE
DSA
CONTACT

● SYSTEM ONLINE

Navigation should move through the world rather than simply exposing unrelated flat sections where practical.

---

# DATA PRINCIPLE

Existing portfolio data is the source of truth.

Do not rewrite:
- project data
- experience data
- skill data
- DSA content
- resume data
- contact information

The immersive layer changes presentation, not content.

---

# TECHNICAL RESPONSIBILITIES

Angular owns:
- application
- content/data
- navigation
- HTML UI
- accessibility
- routing

Three.js owns:
- world
- geometry
- nodes
- connections
- particles
- materials
- lighting
- camera

GSAP owns:
- scroll choreography
- camera choreography
- transformations
- transitions
- UI synchronization

---

# RESPONSIVE

Desktop: full immersive world and spatial depth.

Tablet: reduced particles, node density, shader complexity and camera travel.

Mobile: simplified 3D experience; prioritize content, interaction and readability. Touch replaces hover.

---

# ACCESSIBILITY

Support keyboard navigation, focus states, readable contrast, reduced motion and WebGL fallback.

With prefers-reduced-motion:
- reduce camera movement
- reduce idle animation
- remove aggressive parallax
- preserve content and interactions

---

# PERFORMANCE

Prefer:
- instancing
- shared geometry/materials
- capped particles
- lightweight shaders
- lazy loading
- no per-frame allocations
- rendering outside Angular
- visibility pause
- device-aware quality

---

# HARD FAILURE CONDITIONS

The final implementation must NOT become:

- dark portfolio + cyan text
- normal portfolio + 3D background
- collection of floating cards
- cyberpunk dashboard
- generic sci-fi website
- stock 3D model showcase
- sequence of fade-in sections
- giant glassmorphism interface

If removing the Three.js canvas leaves a website that looks almost the same, the immersive design has failed.

---

# FINAL EXPERIENCE TEST

System Entry: Do I feel like I entered something?

Core: Does it feel like the center of an engineering system?

Architecture: Does the Core physically become architecture?

Projects: Do projects feel like systems rather than cards?

Experience: Does the career feel like a journey rather than a timeline?

DSA: Does DSA feel like problem solving rather than a list?

Collapse: Does everything meaningfully return to the Core?

Contact: Does the experience end naturally?

Target reaction:

> “I am exploring the architecture of an engineer.”

Master principle:

> **The visitor does not scroll through the portfolio. The visitor travels through the system.**

The 3D world is not decoration.

**The 3D world IS the portfolio experience.**
